# ComboLite 插件间通讯设计文档

> **版本**：v1.0
> **适用框架**：ComboLite v2.0 插件化框架
> **实践案例**：home 插件 → geokori 插件（轨迹记录控制与状态订阅）

## 一、背景与约束

ComboLite 下所有插件运行在**宿主同一进程**中，共享宿主 uid 与宿主 ClassLoader 加载的公共库。这一前提决定了插件间通讯的设计边界：

| 约束 | 含义 | 对通讯设计的影响 |
|------|------|------------------|
| 同进程 | 无 IPC 开销，可直接传递对象 | 性能不是瓶颈，选型看解耦与可维护性 |
| 共享 uid | 进程内任何代码可互发广播、互调服务 | 安全边界 = 安装时的签名校验，而非运行时的通讯层 |
| 多 ClassLoader | 每个插件一个 `PluginClassLoader` | **契约类型必须由宿主加载**，否则两份类副本无法互转（`ClassCastException`） |
| 全局类索引 | 安装时用 dexlib2 扫描 APK 生成 `class_index` | `getInterface` 按类名查找是 O(1)，但索引**安装时固化** |
| 链式重启 | 热更新插件会级联重启依赖方 | 应尽量减少插件间的编译期依赖，控制依赖图规模 |

## 二、通讯方式总览与选型

ComboLite 提供三种官方机制，外加它们的组合：

| 机制 | 方向 | 类型安全 | 回执/订阅 | 耦合点 | 适用场景 |
|------|------|---------|----------|--------|---------|
| `PluginManager.getInterface(iface, className)` | 请求-响应 | 强（编译期接口） | ✔ 可拿返回值、订阅 `StateFlow` | 共享 lib 中的一个接口 | 服务调用、状态订阅、需要回执 |
| `Context.sendInternalBroadcast(action)` | 单向通知 | 弱（字符串 + extras） | ✗ fire-and-forget | action 常量 | 命令下发、"通知插件干活"、事件广播 |
| ContentProvider（`xxxPlugin` 系列扩展） | 数据 CRUD | 中（Uri 契约） | ✔（查询即回执） | Uri 约定 | 跨插件数据共享、结构化数据 |

**选型原则**：

1. 需要**回执或订阅状态** → `getInterface`；
2. 纯**单向命令**、发送方不关心结果 → 广播；
3. **结构化数据共享**（数据库式） → ContentProvider；
4. 命令 + 状态都要（最常见）→ **混合方案**：命令走广播、状态走接口。两者耦合点都很薄（一个字符串常量 / 一个接口），且互不阻塞。

## 三、方式一：getInterface 服务发现

### 3.1 原理

```
调用方                        ComboLite                      实现方插件
  │                              │                              │
  │ getInterface(Ifaces::class, "org.x.Impl")                   │
  │ ───────────────────────────> │                              │
  │                              │ 查全局类索引 Map<类名, 插件ID> │
  │                              │ ───────────────────────────> │
  │                              │ 反射实例化（要求无参构造）       │
  │<─────────────────────────────│ 返回接口实例（宿主 iface Class）│
```

- 按**类名字符串**定位实现，调用方与实现方插件**互不依赖**（无类加载委托关系，热更新不引发链式重启）；
- 接口 `Class` 由宿主 ClassLoader 加载，返回对象可安全强转。

### 3.2 三条硬性约束

| 约束 | 原因 | 违反后果 |
|------|------|---------|
| ① 接口定义在宿主 `implementation` 的模块（如 lib-geokori），插件一律 `compileOnly` | 接口类必须全局唯一 | 两个插件各加载一份接口 → 返回对象 `ClassCastException` |
| ② 实现类必须有无参构造函数 | 框架反射实例化 | 实例化失败返回 null |
| ③ 实现类必须 ProGuard keep | 类索引是**类名字符串** | 混淆后类名对不上，索引命中但类加载失败 |

```proguard
-keep class org.kori.plugin.geo.GeoTrackStateApiImpl { <init>(); }
```

### 3.3 标准结构

**宿主 lib（契约）**：

```kotlin
package org.cwcc.open.geokori.api

interface ITrackRecordingStateApi {
    val isRecording: StateFlow<Boolean>
    val isPaused: StateFlow<Boolean>
}
```

**实现方插件**：

```kotlin
package org.kori.plugin.geo   // ★ 包名即 IMPL_CLASS 的一部分，见 9.x 陷阱

class GeoTrackStateApiImpl : ITrackRecordingStateApi {
    override val isRecording = TrackRecordingEngine.state
        .map { it.recording }
        .stateIn(scope, SharingStarted.Eagerly, false)
    // ...
}
```

**调用方插件（桥接，懒解析 + 兜底）**：

```kotlin
object TrackStateBridge {
    private const val IMPL_CLASS = "org.kori.plugin.geo.GeoTrackStateApiImpl" // 全限定名

    private val api: ITrackRecordingStateApi?
        get() = runCatching {
            PluginManager.getInterface(ITrackRecordingStateApi::class.java, IMPL_CLASS)
        }.getOrNull()

    fun isRecordingFlow(): StateFlow<Boolean> = api?.isRecording ?: MutableStateFlow(false)
}
```

## 四、方式二：sendInternalBroadcast 消息机制

### 4.1 结构

- **契约**：action 字符串常量集中定义在宿主 lib（`TrackIntents`），两端 `compileOnly` 引用——不要手写魔法字符串；
- **发送**：`context.sendInternalBroadcast(TrackIntents.ACTION_TOGGLE) { ... }`；
- **接收**：实现方插件用**动态 Receiver** 注册，`RECEIVER_NOT_EXPORTED`（应用内部广播，Android 13+ 强制）；
- **extras 只用基本类型**（String/Boolean/Int/Long），不传自定义 Parcelable，避免反序列化时跨 ClassLoader 找不到类。

### 4.2 参考实现

```kotlin
object TrackIntents {
    const val ACTION_START  = "org.kori.plugin.geo.track.ACTION_START"
    const val ACTION_PAUSE  = "org.kori.plugin.geo.track.ACTION_PAUSE"
    const val ACTION_RESUME = "org.kori.plugin.geo.track.ACTION_RESUME"
    const val ACTION_STOP   = "org.kori.plugin.geo.track.ACTION_STOP"
    const val ACTION_TOGGLE = "org.kori.plugin.geo.track.ACTION_TOGGLE"
    const val EXTRA_NAME_HINT = "extra_name_hint"
    val ALL_ACTIONS = listOf(ACTION_START, ACTION_PAUSE, ACTION_RESUME, ACTION_STOP, ACTION_TOGGLE)
}

class TrackCommandReceiver : BroadcastReceiver() {
    override fun onReceive(context: Context, intent: Intent) {
        when (intent.action) {
            TrackIntents.ACTION_START -> TrackRecordingEngine.start(context.applicationContext,
                nameHint = intent.getStringExtra(TrackIntents.EXTRA_NAME_HINT))
            TrackIntents.ACTION_TOGGLE -> TrackRecordingEngine.toggle(context.applicationContext)
            // ...
        }
    }

    @Volatile private var registeredContext: Context? = null

    fun register(context: Context) {
        ContextCompat.registerReceiver(
            context.applicationContext, this,
            IntentFilter().apply { TrackIntents.ALL_ACTIONS.forEach { addAction(it) } },
            ContextCompat.RECEIVER_NOT_EXPORTED,
        )
        registeredContext = context.applicationContext
    }

    fun unregister() = runCatching {
        registeredContext?.unregisterReceiver(this); registeredContext = null
    }
}
```

在实现方插件入口注册/注销：

```kotlin
override fun onLoad(context: PluginContext) {
    trackCommandReceiver.register(context.application)   // ★ 漏注册 = 消息石沉大海
}
override fun onUnload() {
    trackCommandReceiver.unregister()
}
```

### 4.3 语义约定

- **幂等**：接收方所有命令处理必须幂等（引擎层的 start/stop 本身幂等）；
- **fire-and-forget**：发送方无回执。接收方插件未加载时消息静默丢弃——这是特性（发送方无需感知对方状态），需要回执的场景不要用广播；
- **无发送方身份**：进程内广播无法可靠识别发送方插件，需要鉴权的命令不要用广播承载（见安全模型）。

## 五、方式三：ContentProvider（数据共享）

适用于跨插件的结构化数据共享（CRUD 场景）。插件端实现标准 `ContentProvider` 并在插件 Manifest 声明，调用方用 `queryPlugin / insertPlugin / updatePlugin / deletePlugin / callPlugin` 扩展函数，框架自动完成 Uri 代理转换。

本项目轨迹场景未使用，详细配置流程见《四大组件指南》第 4 章。

## 六、混合方案实践：轨迹记录

### 6.1 架构

```
┌────────────────────────────────────────────────────────────────┐
│ 宿主 app（implementation，宿主 ClassLoader 统一加载）              │
│   lib-geokori                                                   │
│     ├── TrackIntents            （广播契约：action 常量）          │
│     ├── ITrackRecordingStateApi （状态契约：接口）                 │
│     └── ui-gesture: stopRecordGuardGesture / StopChargingOverlay│
├────────────────────────────────────────────────────────────────┤
│  home 插件（compileOnly 引用 lib-geokori / ui-geokori）         │
│    GeoKoriCenter 的 PUBLISH 按钮                                │
│      ├─ 命令：sendInternalBroadcast(ACTION_TOGGLE) ─────────┐   │
│      └─ 状态：TrackStateBridge.getInterface(...) 订阅 isRecording│
│                                                            │   │
│  geokori 插件                                              │   │
│    TrackCommandReceiver（onLoad 注册）←────────────────────┘   │
│      → TrackRecordingEngine.start / stop                       │
│    GeoTrackStateApiImpl → 投影 isRecording / isPaused          │
│    HUD / 地图（录制开始后由 Engine.state 驱动显示）                │
└────────────────────────────────────────────────────────────────┘
```

### 6.2 交互时序

```
未记录   PUBLISH=蓝➕  单击 → 广播 ACTION_TOGGLE → Engine.start() → FGS+HUD 出现
录制中   PUBLISH=红⛔  isRecording StateFlow 驱动按钮态；stopGuard 手势启用：
                      单击无效（提示"再点 N 次"）/ 4 连击 / 长按 5s（全屏充能环）
确认     onStop → handleItemClick → 广播 ACTION_TOGGLE → Engine.stop()
```

结束操作的可视化（充能环）在宿主侧完成，**消息仍在确认后才发出**——长按中途松手不发任何消息。

### 6.3 文件归属与依赖矩阵

| 文件 | 归属模块 | 依赖方式 |
|------|---------|---------|
| `TrackIntents`、`ITrackRecordingStateApi` | lib-geokori | 宿主 `implementation` |
| `TrackCommandReceiver`、`GeoTrackStateApiImpl` | geokori 插件 | `compileOnly(lib-geokori)` |
| `TrackStateBridge` | home 插件 | `compileOnly(lib-geokori)` |
| `GeoKoriCenterToolBar`（stopGuard 手势） | ui-geokori | 宿主 `implementation`，插件 `compileOnly` |
| `StopRecordGuardGesture` / `StopChargingOverlay` | ui-geokori（gesture 包） | 同上 |

## 七、安全模型

1. **信任边界在安装时**：`InstallerManager` 签名校验（`Strict` 同签 / `UserGrant` / `Insecure`）+ `AuthorizationManager` 管控高危 API。能装进来的插件即视为可信。
2. **进程内通讯不做运行时鉴权**：同 uid 下任何插件都能发广播、调 `getInterface`——这是开放插件模型的固有特性，靠 obscurity（改 action 名）或 receiver permission 都挡不住进程内代码，不必投入。
3. **恶意插件的危害面远大于"发一条命令"**：它本来就能读定位、写文件。防护重点是**别装进来**（保持 `Strict` 策略），而不是装进来之后拦通讯。
4. **透明度兜底**：高危操作（开始记录等）触发时给出用户可见反馈（FGS 通知、HUD、Toast），让任何来源的触发可感知。

## 八、生命周期与热更新

| 时机 | 影响 | 对策 |
|------|------|------|
| 插件安装/更新 | 重新生成类索引；旧索引里没有新增类 | 新增实现类后必须重新安装该插件，否则 `getInterface` 找不到 |
| geokori 热更新 | Engine 单例随旧 ClassLoader 销毁，新实例重建 | 状态接口每次按需解析（`TrackStateBridge.api` 不缓存实例）；Receiver 在 `onLoad/onUnload` 成对注册注销 |
| home 早于 geokori 加载 | 首次解析拿不到接口 | 状态桥以 `PluginManager.loadedPluginsFlow` / `available` 为 remember key，加载完成后自动重解析；UI 用默认态兜底 |

## 九、常见陷阱与排查清单

按本项目实际踩坑排序：

| # | 症状 | 根因 | 对策 |
|---|------|------|------|
| 1 | 广播发了对方没反应 | 接收方 `onLoad` 漏注册 Receiver | 入口类注册/注销成对出现，代码评审 checklist |
| 2 | 状态永远 false、按钮不变色 | **`IMPL_CLASS` 字符串与实现类实际包名不一致**（字符串契约编译期不检查） | 改包名时全局搜同步；可写单测断言 `Impl::class.java.name == 桥中常量` |
| 3 | 状态拿不到，geokori 明明已加载 | 接口 import 包名两端不一致（一边 `.api` 一边 `.map`） | 契约类只定义一处，两端从同一包 import |
| 4 | 新增实现类后 getInterface 找不到 | 类索引安装时生成，未重新安装插件 | 更新插件后重新安装 |
| 5 | `ClassCastException` | 某插件用 `implementation` 引入了应共享的模块，出现两份类 | 严格执行 compileOnly 铁律；用 ClassLoader 日志验证 |
| 6 | 返回对象行为异常（状态改了 UI 不变） | 调用方缓存了接口实例，热更新后指向旧 ClassLoader | 按需即时解析，不长期缓存跨插件实例 |
| 7 | 收不到广播（Android 13+） | 注册时未传 `RECEIVER_NOT_EXPORTED/EXPORTED` | 内部广播统一 `NOT_EXPORTED` |
| 8 | 手势与 clickable 同时响应 | 防误触手势（detectTapGestures）与 clickable 叠加同节点 | 互斥挂载：guard 模式不挂 clickable |
| 9 | 手势内编译报 Restricted suspending | `awaitPointerEvent` 等受限函数被包进 `withTimeoutOrNull` | 受限函数只能在手势协程本体调用；超时判定交给 `tryAwaitRelease`/外层框架 |

**排查三板斧**：

1. **日志**：接收方 `onReceive` 打 action；桥接 `refreshAvailability()` 打可用性；`handleItemClick` 打 id + stopGuard 值；
2. **ClassLoader 验证**：

```kotlin
Log.d("CL", "接口 CL: ${ITrackRecordingStateApi::class.java.classLoader}")
Log.d("CL", "实现 CL: ${GeoTrackStateApiImpl::class.java.classLoader}")   // 应与接口不同（插件 CL）
Log.d("CL", "本插件 CL: ${this::class.java.classLoader}")                  // 与实现相同
```

3. **二分定位**：命令不通查 Receiver；状态不通查 `getInterface` 三要素（类名 / 接口包名 / 索引）。

## 十、工程规范建议

1. **契约集中**：所有跨插件 action 常量、接口统一放 `lib-geokori` 的 `api` 包，禁止散落于业务代码；
2. **命名约定**：action = `插件包名.功能.ACTION_动词`；桥接类 = `XxxBridge`；实现类 = `XxxApiImpl`；
3. **注释标注字符串契约**：`IMPL_CLASS` 旁注释"改包名必须同步改这里"；
4. **默认兜底**：任何 `getInterface`/广播调用都 `runCatching` + 默认值，对方不存在时 UI 显示默认态而非崩溃；
5. **文档同步**：本文件随架构演进更新；新增通讯通道时在"文件归属与依赖矩阵"登记一行；
6. **调试开关**：Debug 构建在桥接层打详细日志（可用性翻转、解析耗时），Release 收敛为 WARN。
